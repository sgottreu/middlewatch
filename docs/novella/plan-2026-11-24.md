# Novellas in middlewatch — plan (2026-11-24)

Kindle novellas move out of the `kindle-novellas` FastAPI app and into this
repo as a third pipeline, beside `story_pipeline` and `ambience_pipeline`, with
its own page in the review UI. The ambience page is planned separately in
[docs/ambience/review-ui-plan-2026-11-24.md](../ambience/review-ui-plan-2026-11-24.md).

## Decisions

- **No FastAPI.** The novella UI is a page in the existing review server
  (`story_pipeline/review/`), so it gets the same sign-in, phone layout and job
  runner. The kindle repo becomes an archive once its work is imported.
- **Namespaces.** Novellas live in `novellas/<series>/<slug>/`, never under
  `stories/` (`bundle_roots` globs `stories/*/*/manifest.json` and would pick
  them up). Jobs run under `runs/novella-<slug>/`. Ledger rows carry
  `pipeline="novella"`. Ambience is the same shape: `ambience/<slug>/`,
  `runs/ambience-<slug>/`, `pipeline="ambience"`.
- **Bibles are read in place** with `bibles.load()`. Development and tests use
  **amberlight** (already promoted). Drafts are not promoted until Scott says
  so; wiring a draft bible in is deferred until then.
- **Tests use fake bibles** (`sample_draft` / `broken_draft` fixtures in
  `tests/conftest.py`). No test reads the in-progress broken-edges or
  north-star drafts.
- **No git from the server.** Versioning is numbered drafts
  (`drafts/04.2.md` + `04.2.review.json`), as stories do; `mw-commit-stories`
  is extended to cover `novellas/`. Kindle's commit-per-step is dropped.

## Package: `novella_pipeline/`

| From kindle `storyflow/` | Becomes |
|---|---|
| `workflow.py` (stages, redraft rule, send back) | `bundle.py` stages `outline → draft → author_edit → review → approve` (`export` later) |
| `store.py` + `status.json` | Bundle-style `manifest.json`, pinned fields, `ledger_story()` |
| `prompts.py`, `parsing.py` | ported; the bible block comes from `Bible.prompt_block()` |
| `agents/draft-writer.md`, `editor.md` | `novella_pipeline/prompts/`, built from `house.md`, `ai-tells.md`, `boundaries.md`, `authors/scott-voice.md`, `genres/*.md` |
| `agents.py` | deleted; everything goes through `story_pipeline.llm` |
| `gitops.py`, `canon_sources.py` | dropped |

Kindle's approve bug (writes before checking the bible exists,
`store.py:282`) is fixed in the port: validate everything, then write.

## CLI and jobs

`python3 -m novella_pipeline.cli outline|draft|review <bundle> [--chapter N]`,
launched from `review/novella_api.py` through
`runner.start_command("novella-<slug>", …)`. The CLI writes model text to the
job log as it streams, so the existing 1.5 s log poll shows the chapter forming.

## Page: `review/novellas.html`

- **Board:** series → novellas → chapters with stage.
- **Chapter:** beats → draft → author edit (textarea, saved via
  `POST /api/novella/<slug>/chapter/<n>`) → review (editor notes beside
  `lint.py` AI-tell findings) → approve. Keep the prompt preview.
- **Canon:** the bible, read-only; approved new details go to the bible's
  changelog via `bible_api`.

Shared `review/common.css` + `common.js` (tabs, job polling, log pane) are
pulled out first so the ambience and novella pages don't copy `app.html`.

## Novella-specific agents

- Outliner: 10–16 chapters, 25–40k words, own validator (`_validate_outline`'s
  4–9 chapters and ~500-word chapters don't apply).
- Writer/editor: Markdown prose, 2.5–4k words per chapter, no speaker segments
  or WPM.
- "Expand to novella": seed from an existing story's `outline.json`, cast and
  beats.
- Optional `novella:` frontmatter block (series arc, book order, POV/tense,
  word target, timeline, voice notes) — allowed by `validate()`, ignored by the
  story pipeline. Added when a bible is promoted for novellas.

## What was built (step 5, novella half, 2026-11-25)

**Package `novella_pipeline/`.** `workflow.py` and `parsing.py` are kindle's,
ported unchanged (same stages, redraft only from Outlined/Drafted, send back to
any earlier stage, Markdown-heading replies). `bundle.py` keeps a book at
`novellas/<series>/<slug>/`:

```
manifest.json            pipeline "novella", slug, pinned title/series/genre/bible/target_words,
                         chapters [{n, title, target_words, stage}], spend
brief.md  outline.md     written by Scott
chapters/NN/beats.md     summary.md (approved)   details.md (approved new details)
drafts/NN.V.md           writer's draft V, never edited
drafts/NN.V.writer.json  its summary, new details, flags, model, note
drafts/NN.V.edit.md      Scott's edit of V (the working text; falls back to the draft)
drafts/NN.V.review.json  editor sections + raw reply + lint findings for that edit
```

A redraft is V+1, so sending a chapter back and redrafting keeps the old draft
and edit. `prompts.py` builds the system prompt from
`novella_pipeline/prompts/{writer,editor}.md` (adapted from kindle's agents) with
`house.md`, `boundaries.md`, `ai-tells.md`, `authors/scott-voice.md` and the genre
guide substituted in, and `{structure}` replaced by a novella length block (10–16
chapters, 2.5–4k words, no WPM). The user message is kindle's shape: bible
(`Bible.prompt_block()`, read in place), brief, outline, earlier summaries,
the chapter tag. `stages.py` calls `story_pipeline.llm.complete` with
`models.novella_writer` / `novella_editor` (both `claude-opus-5`, priced) and
records spend with `spend.record_llm` (ledger `pipeline="novella"`, stages
`draft` / `review`). `lint_md.py` runs `lint.lint_chapter` over the Markdown
(one segment per paragraph, `* * *` as a break) and the findings are stored
with the review.

**CLI.** `python3 -m novella_pipeline.cli new | beats | draft | review | approve |
send-back | status`. `<bundle>` is a path or a slug. `draft`/`review` stream the
reply to stdout and emit `::progress` start/done markers under `MW_PROGRESS`.

**Page.** `/novellas` (`review/novellas.html`, common.css/js) with the plugin
`review/novella_api.py`: Board, Book (chapters, brief, outline), Chapter
(beats → draft with prompt preview and note → author edit → review with editor
notes beside lint findings → approve with summary and picked new details,
send back, versions), Canon (prompt block + changelog, read-only). Jobs run as
`runs/novella-<slug>/` via `runner.start_command(..., pipeline="novella")`.
Add `["Novellas", "/novellas"]` to `MW.PAGES` in common.js to show the tab.

**Departures from kindle.**

- Approve validates everything (stage, summary, bible exists) before writing.
  New details go to the bible's **changelog** (`kind` novella), never the
  bible body — kindle appended a "Story Additions" section to `bible.md`.
- No git commit per step; numbered versions instead.
- No prompt caching: `llm.complete` sends one plain-text user turn, so kindle's
  `cache_control` on the canon block is gone. Worth adding to `llm.py` if
  per-chapter input cost matters.
- No server-side model fallback (kindle's beta `fallbacks`), and no
  "regenerate summary" call: the approve form starts from the writer's summary.
- Chapters are added by hand (CLI `beats` or the page) until the outliner
  (step 6) exists.
- `house.md` is written for narration; the novella prompts say to read
  "listener" as "reader" and that the novella file wins on form. The linter's
  narration rules (long sentences, clause chains, break anchoring) still run as
  warnings.

**Not done here:** outliner, "Expand to novella", the `novella:` frontmatter
block (step 6); `mw-commit-stories` does not yet cover `novellas/`; `MW.PAGES`.
